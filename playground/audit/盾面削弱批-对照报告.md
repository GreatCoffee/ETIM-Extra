```java
package io.github.etim.etim.combat;

import net.minecraft.util.DamageSource;

/**
 * 盾的**数值契约**（盾面削弱批 M-1/M-2；签名 D-5 冻结，变更走主账本 + 通知附属）。
 *
 * <p>两道方法都吃 {@link DamageSource}：银盾的幽魂面（40+25=65% / 磨率 0.5×）**只能**
 * 由来源区分。返回的是**减伤比例**（不是保留系数——与 {@code ETIMConfig.blockDamageFactor}
 * 语义相反，木盾两者数值巧合相等 1−0.5=0.5）。</p>
 *
 * <p>The numeric contract of a shield. The main mod owns "how to compute"; the
 * add-on owns "how much". Both take the source because the silver shield has
 * two faces that only the source can tell apart. Published = frozen API.</p>
 */
public interface ETIMShield {

    /** 被挡掉的比例 0..1。Fraction of incoming damage the shield removes, 0..1. */
    default float getBlockReduction(DamageSource source) {
        return ETIMConfig.shieldWoodReduction;      // 木盾缺省 0.5（D-4 ①）
    }

    /** 磨率乘子（基准率在 config，木盾 = 1.0）。Wear-rate multiplier; base rate in config. */
    default float getWearMultiplier(DamageSource source) {
        return 1.0F;                                // 木盾缺省 1.0（M-2 ③）
    }
}
```

### 1.2 `combat/ETIMGhost.java`（**新增**，幽魂位）

| 项 | 内容 |
|---|---|
| 职责 | 「攻击者是幽魂」的**侧表**判定（D-1 已裁形态）：`WeakSet`（`Collections.synchronizedSet` 包一层），零 mixin、零 `DamageSource` 字段 |
| 形态依据 | R196 银位是「单字段 + 读/写两法」（`DamageSource.java:37`、`:213-215`、`:222-225`）；本批取**结构等价、语义相反**的侧表（C-2：R196 是"攻击者持银"） |
| 类型门 | **只收 `EntityDamageSource`**（`util\EntityDamageSource.java:13-19`）；其余一律拒绝并打 `[BlockLog] ghost-mark rejected` |
| 单例风险（C 级） | `WeakSet` 的键只需**逐次 `new`** 的源；静态单例（`DamageSource.MAGIC` 一类）会被静态字段永久持有 ⇒ **调用点必须只传逐次新建**（§6.3） |
| 判行锚 | W-19（`spectral=true/false`） |

```java
package io.github.etim.etim.combat;

import java.util.Collections;
import java.util.Set;
import java.util.WeakHashMap;

import net.minecraft.util.DamageSource;
import net.minecraft.util.EntityDamageSource;

/**
 * 幽魂位（盾面削弱批 M-6 / D-1 已裁）：**攻击者是幽魂**这一事实的侧表。
 *
 * <p>形态：{@code WeakSet<DamageSource>}——源对象逐次新建、用完即弃，弱引用不阻回收。
 * 语义与 R196 {@code DamageSource.hasSilverAspect}（DamageSource.java:213-225）**相反**：
 * R196 记"攻击者持银"，这里记"攻击者是幽魂"；两者都只在**攻击侧**上标、消费侧只读。</p>
 *
 * <p>侧表而非字段：不改 {@code DamageSource} 类、不加 mixin，附属只读一个静态方法。</p>
 */
public final class ETIMGhost {

    /** 弱引用集合：键不阻回收，静态单例也只会泄漏一条目（且被类型门挡在门外）。 */
    private static final Set<DamageSource> SPECTRAL = Collections.synchronizedSet(
            Collections.newSetFromMap(new WeakHashMap<DamageSource, Boolean>()));

    private ETIMGhost() {
    }

    /**
     * 上标。**只接受逐次新建的 {@link EntityDamageSource}**（D-1 类型门）：
     * 静态单例一旦上标会污染该源之后的所有攻击，故直接拒绝并留判行。
     *
     * @return true = 源**现已**上标（重复调用幂等，恒 true）；false = 被类型门拒绝
     */
    public static boolean markSpectral(DamageSource source) {
        if (!(source instanceof EntityDamageSource)) {
            ETIMBlockLog.ghostRejected(source);     // [BlockLog] ghost-mark rejected src=<type>
            return false;
        }
        SPECTRAL.add(source);
        return true;                                 // 不用 Set.add 返回值：重复上标也算成功
    }

    /** 只读。消费侧唯一入口（附件盾的 {@code getBlockReduction} 调它）。 */
    public static boolean isSpectral(DamageSource source) {
        return source != null && SPECTRAL.contains(source);
    }
}
```

## §4 浮点 epsilon 的落码位置（任务书 ①）

### 4.1 落点

**唯一落点**：`combat\ETIMBlocking.java` 的磨损臂，两处（盾接口支 + 木盾支）：

```java
wear = (int) Math.floor(blocked * (double) rate + 1.0E-4);   // 盾两臂
```

**不加的地方**：工具臂保持 `wear = (int) (blocked * decay);`（`combat\ETIMBlocking.java:147` 原式，M-3 ③「一字不动」）。理由：工具磨损是 R196 `Damage.java:203-208` 的整数语义，`decay` 是整十数，加 epsilon 会改变既有工具的边界行为（属越批改动）。

`1.0E-4` 的取值先例：`combat\R196ArmorModel.java:62`（`ROUND_TOLERANCE = 1.0E-4F`，护甲取整容差）。

### 4.2 为什么必须加（真机实测）

按裁定式 `net = max(1.0, raw × (1 − r))`（float）+ `x = net × rate × mult`（double），在 **OpenJDK 21** 上逐格实测 21 格：**2 格翻转，19 格不受影响**。

| 盾 / 伤害 | net（float） | x = net × rate × mult | 裸 `(int)x` | `floor(x+1e-4)` | 表值 wear | 后果（若不加） |
|---|---|---|---|---|---|---|
| **铜 8 伤** | 3.599999905 | **8.999999761581** | **8** | **9** | 9 | 击数 200（应 178，**+12%**） |
| **艾德曼 8 伤** | 1.599999905 | **3.999999761581** | **3** | **4** | 4 | 击数 4,267（应 3,200，**+33%**） |
| 其余 19 格 | — | — | 与 `floor(x+1e-4)` 同值 | 同值 | 同表 | 无差异 |

**三条实测结论**：① **受影响的是 2 格不是 1 格**——铜 8 伤同样翻转（主会话回执只列了艾德曼；`Cu 8 伤 = 9.000001` 这一写法来自"先乘 rate 再乘系数"的另一种算序，本式 `net` 先落 float 再乘，得 8.9999998）；② 乘序不影响结果（net-first / rate-first / 左到右三种算序在 3 个临界格上给同一个 `(int)`）；③ 取 `1e-4` 后 21 格全部落到表值，**且不产生任何额外修正**（19 格原样）；④ **精度口径**：上表是**落码式**（`blocked` float、`rate` 提升 double）的结果——若两因子全程 float 乘，铜 8 伤会舍成 `9.0f` 而不翻（届时只有艾德曼 1 格），两种算序都必须加 `1e-4`（摸底 §2.7/§3.1 同句）。

### 4.3 判据行

`[BlockLog] wear` 行的 `wear=` 必须与 §5 表逐格相同；铜盾 8 伤若出现 `wear=8` 即 epsilon 漏加（不是数值设计问题）。
